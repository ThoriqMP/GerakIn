# Laporan Audit Anti-Slop (Audit-002)
**Proyek:** GerakIn (Workout & Habit Tracker)  
**Tanggal:** 20 Oktober 2026  
**Auditor:** Anti-Slop System Filter  
**Status:** Perbaikan Selesai & Terverifikasi (29/29 Unit & Feature Tests PASS)

Dokumen ini memuat audit mendalam terhadap alur registrasi, login, sesi autentikasi, serta persistensi database pada lingkungan lokal dan deployment serverless Vercel.

---

## Ringkasan Eksekutif & Investigasi Masalah User

User melaporkan:
> *"ada masalah pada register dan login, saya coba bikin akun tapi seperti nya tidak tersimpan ke database... dia berhasil masuk namun ga lama dia akan ke logout. terus kemudian saat mau loigin lagi dengan akun yang baru didaftyarkan tadi malah ada notifikasi email atau kata sandi tidak cocok. mohon diaudit dan dilakukan perbaikan"*

### Akar Penyebab Teknis (Root Causes):
1. **Sifat Ephemeral SQLite di Serverless Vercel (Penyebab Utama Data Hilang & Ter-logout):**
   Pada berkas `vercel.json`, koneksi di-hardcode ke `DB_CONNECTION: sqlite` dan `DB_DATABASE: /tmp/database.sqlite`. Pada platform serverless AWS Lambda / Vercel, direktori `/tmp` bersifat terisolasi per kontainer dan dihapus saat kontainer *cold-restart*. Setiap request baru atau perpindahan *edge region* dapat diarahkan ke kontainer Lambda berbeda yang memiliki database kosong. Kontainer baru menjalankan `migrate` dan `db:seed` (hanya membuat akun Budi Prakoso), sehingga user ID yang baru terdaftar tidak ditemukan di kontainer tersebut. Laravel mendeteksi user ID tidak valid di sesi cookie, lalu langsung memaksa logout (`Auth::logout`). Ketika user mencoba login kembali, kontainer mencari akun di SQLite barunya dan tidak menemukannya, memunculkan notifikasi *"Email atau kata sandi tidak cocok"*.
2. **Keterbatasan Validasi Input Login (Email vs Username):**
   Formulir pendaftaran meminta Nama, Username, Email, dan Password. Namun di form login sebelumnya, input diwajibkan berupa format email valid (`'email' => 'required|email'`). Jika user memasukkan username mereka, sistem menolak atau gagal login.
3. **Sensitivitas Huruf Besar/Kecil (Case Sensitivity) & Whitespace:**
   Di registrasi, email dinormalisasi menjadi huruf kecil (`Str::lower($validated['email'])`), namun di login sebelumnya input email tidak di-trim dan tidak di-lowercase. Pada database cloud (khususnya PostgreSQL seperti Supabase/Neon), pencarian string bersifat *case-sensitive*, menyebabkan kegagalan autentikasi jika keyboard HP otomatis mengkapitalkan huruf pertama (misal `User@gmail.com`).
4. **Resiko Double-Hashing Password:**
   Model `User` Laravel 11 sudah memiliki `'password' => 'hashed'` pada method `casts()`. Pemanggilan berulang `Hash::make()` di controller berpotensi menyebabkan double-hashing jika tidak ditangani dengan benar.

## Daftar Temuan (Numbered Findings List)

### #001 [HIGH] Konfigurasi Database Serverless Vercel Mengunci SQLite Tanpa Opsi Cloud DB
* **Aturan Terlanggar:** R-26 (Interactive Elements & Functional Completeness), C-4 (Resilience)
* **Berkas:** `vercel.json`, `api/index.php`, `config/database.php`
* **Alasan:** SQLite di serverless Vercel tidak persisten antar lambda container sehingga akun yang baru dibuat hilang seketika saat request dialihkan ke container lain.
* **Tindakan Perbaikan yang Telah Dilakukan:**
  1. Menghapus hardcode `DB_CONNECTION` dan `DB_DATABASE` statis dari `vercel.json` agar variabel lingkungan Vercel dapat mengontrol koneksi database secara dinamis.
  2. Memperbarui `config/database.php` agar secara otomatis mendeteksi URL cloud database (`DATABASE_URL`, `POSTGRES_URL`, atau `DB_URL`) dan otomatis beralih ke driver `pgsql` atau `mysql`.
  3. Memperbarui `api/index.php` agar mengenali `DATABASE_URL` (PostgreSQL / Supabase / Neon / MySQL). Jika tidak ada cloud DB yang dipasang, sistem menggunakan fallback cerdas dengan menyalin berkas seed SQLite `database/database.sqlite` daripada membuat file 0-byte kosong.

---

### #002 [HIGH] Autentikasi Login Mendukung Email Maupun Username dengan Normalisasi Input
* **Aturan Terlanggar:** R-26 (Functional Completeness), C-1 (Intentionality)
* **Berkas:** `app/Http/Controllers/AuthController.php`, `resources/views/auth/login.blade.php`
* **Alasan:** User yang mendaftar sering kali mencoba masuk menggunakan username mereka daripada email, atau mengalami typo kapitalisasi otomatis dari keyboard smartphone.
* **Tindakan Perbaikan yang Telah Dilakukan:**
  1. Mengubah validasi login di `AuthController::login` dari strictly email menjadi `required|string`.
  2. Menambahkan deteksi otomatis apakah input berupa email (`filter_var($input, FILTER_VALIDATE_EMAIL)`) atau username, lalu menormalisasi huruf kecil (`Str::lower`) dan membuang spasi (`trim`).
  3. Mengubah label login di Blade dari "Email" menjadi "Email atau Username", tipe input menjadi `type="text"`, dan placeholder informatif `nama@email.com atau username`.

---

### #003 [MEDIUM] Standardisasi Hashing Password pada Model Casts Laravel 11
* **Aturan Terlanggar:** R-26 (Functional Completeness)
* **Berkas:** `app/Http/Controllers/AuthController.php`
* **Alasan:** Model `User` sudah mendefinisikan `'password' => 'hashed'` di `casts()`, sehingga controller sebaiknya meneruskan string password bersih untuk dienkripsi oleh Eloquent secara konsisten.
* **Tindakan Perbaikan yang Telah Dilakukan:**
  1. Pada `AuthController::register` dan `freshDemoUser`, password diteruskan langsung tanpa enkripsi ganda, membiarkan cast Eloquent Laravel 11 menangani bcrypt hashing secara aman.

---

* **Berkas:** `tests/Feature/AuthAndOnboardingTest.php`
* **Alasan:** Test suite sebelumnya belum menguji login ulang setelah akun baru didaftarkan, login dengan username, serta normalisasi whitespace/case.
* **Tindakan Perbaikan yang Telah Dilakukan:**
  1. Menambahkan `test_registered_user_can_login_with_email`.
  2. Menambahkan `test_registered_user_can_login_with_username`.
  3. Menambahkan `test_login_normalizes_case_and_whitespace`.
  4. Menambahkan `test_login_fails_with_wrong_password`.
